# Door 404 workflow

- Inspect only files directly relevant to the task.
- Make the smallest safe change that solves the verified problem.
- Reuse known state; avoid repeated repository scans and research.
- Batch related reads and independent checks.
- Run only tests that cover the change.
- Keep updates and final responses extremely short.
- Prefer GitHub for code and WordPress REST API for live content.
- Use the browser only for required visual or interactive verification.
- Never commit, print, or expose credentials.
- Never commit the database, uploads, caches, backups, or logs.
- Never make destructive production changes without explicit approval.
- Treat repository changes as non-live until deployment is configured and verified.
